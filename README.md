## 🔊 Voice / Яндекс Станция и Алиса

| Файл | Описание | Установка |
| ---- | -------- | --------- |
| [**script/alice_smart_speaker_parallel.yaml**](https://github.com/BrainDeLook/home-assistant-blueprints/blob/main/script/alice_smart_speaker_parallel.yaml) | **[RU]** Скрипт «Алиса: Умный рупор» для озвучивания уведомлений и выполнения команд на одной или нескольких колонках Яндекс Станции. Умные стратегии громкости с возвратом исходного уровня у каждой колонки, голоса, эффекты (шёпот, мегафон и др.) и большая база звуков. **Отличие от оригинала: запускается в режиме `parallel`, поэтому вызовы для разных колонок с разными текстами выполняются одновременно, а не по очереди.** | [![Import Blueprint](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fraw.githubusercontent.com%2FBrainDeLook%2Fhome-assistant-blueprints%2Fmain%2Fscript%2Falice_smart_speaker_parallel.yaml) |

**Требования:** интеграция [YandexStation](https://github.com/AlexxIT/YandexStation) (`media_player` колонок и `tts.yandex_station_say`).

**Как пользоваться:**

1. Импортируйте блюпринт кнопкой выше.
2. Перейдите в **Настройки → Автоматизации и сцены → Скрипты → Добавить скрипт → Использовать проект** и выберите «Алиса: Умный рупор (параллельный)».
3. Сохраните скрипт.
4. В автоматизации в блоке «Тогда» выберите **Выполнить действие** и найдите свой скрипт. Укажите колонку, текст, громкость, голос и эффект.

**Ограничение параллельного режима:** не вызывайте скрипт одновременно для одной и той же колонки. Запуски могут конфликтовать при установке и возврате громкости. Для разных колонок проблемы нет.

**Если нужна очередь:** используйте оригинальный блюпринт (режим `queued`).

**Благодарности:** основано на блюпринте [Eugen417/homeassistant-blueprints](https://github.com/Eugen417/homeassistant-blueprints/blob/main/script/ya_st_alice_simple.yaml) (v4.7). Единственное функциональное изменение: режим запуска `queued` заменён на `parallel`.

## 🤖 Dreame / Свет вслед за пылесосом

**Одна автоматизация для всех комнат. Без ID карты и комнат.**

| Файл | Описание | Установка |
| ---- | -------- | --------- |
| [**dreame_room_lights.yaml**](dreame_room_lights.yaml) | Список комнат с кнопкой добавления. Для каждой записи: название из приложения Dreame, светильники, цвет и яркость. Сохранение и восстановление света, задержка переключения и немедленное восстановление на базе. | [![Import Blueprint](https://my.home-assistant.io/badges/blueprint_import.svg)](https://my.home-assistant.io/redirect/blueprint_import/?blueprint_url=https%3A%2F%2Fgithub.com%2FBrainDeLook%2Fhome-assistant-blueprints%2Fblob%2Fmain%2Fdreame_room_lights.yaml) |

**Требования:** Home Assistant **2026.9+** (форма добавления комнат) и интеграция Dreame с атрибутами `rooms`, `current_segment`, `selected_map` и `docked` у сущности пылесоса. Карта и ID определяются автоматически.

### Настроить один раз

1. Импортируйте блюпринт кнопкой выше и создайте **одну** автоматизацию «Свет вслед за пылесосом».
2. В разделе **«1. Пылесос и комнаты»** выберите своего Dreame.
3. В списке **«Комнаты и светильники»** нажмите кнопку добавления. Впишите название комнаты **как на карте в приложении Dreame**, например «Кухня». Регистр букв и пробелы по краям не важны.
4. В этой записи выберите светильники кухни. При желании задайте её яркость и цвет. Остальные поля можно не заполнять: используются общие настройки из раздела 3 — по умолчанию голубой свет и 70% яркости.
5. Добавьте остальные комнаты **в тот же список**. Сохраните автоматизацию.
6. Для проверки нажмите **«Выполнить действия»** в меню этой автоматизации. В уведомлениях Home Assistant появятся названия комнат из пылесоса и результат сопоставления. Свет при проверке **не меняется**. Если название не найдено, скопируйте правильное из уведомления.

**Пример заполнения формы:**

| Название комнаты в приложении | Светильники | Яркость | Режим | Цвет |
| --- | --- | --- | --- | --- |
| Кухня | Выберите лампы кухни | 70% | Цвет RGB | Голубой |
| Гостиная | Выберите лампы гостиной | 40% | Цвет RGB | Фиолетовый |
| Спальня | Выберите свет спальни | 20% | Температура белого | 2700 K |

Это пример, а не предустановленный список: используйте названия именно с вашей карты. При желании можно добавить несколько записей с одинаковым названием комнаты для разных ламп и настроек. Каждый светильник должен встречаться только в одной записи. Выбирайте отдельные `light`, не группы; для обычной белой лампы выбирайте подходящий режим вместо RGB.

### Как работает

Переход подтверждается после **3 секунд** стабильного положения. Любое изменение комнаты или карты начинает отсчёт заново. Короткий скачок через границу не меняет свет. Задержку можно изменить в разделе 2 или поставить **0**.

После подтверждения блюпринт сначала восстанавливает покинутую комнату, затем сохраняет свет новой комнаты и включает её настройки. При повторном въезде создаётся новый снимок актуального состояния. В комнате без настройки света прежняя комната восстанавливается, новая не меняется.

При `docked: true` восстанавливаются все активные снимки без ожидания таймера: это работает и при промежуточной мойке, и после завершённой зарядки. При паузе внутри комнаты свет остаётся до выезда. При недоступности пылесоса свет восстанавливается после установленной задержки.

### Условие солнца для каждой комнаты

В записи комнаты есть необязательное поле **«Когда включать свет»**:

- **Всегда** — прежнее поведение, также используется при незаполненном поле.
- **Только когда солнце над горизонтом** — включать свет при `sun.sun: above_horizon`.
- **Только когда солнце ниже горизонта** — включать свет при `sun.sun: below_horizon`.

Например, для кухни выберите «Только когда солнце ниже горизонта». Днём блюпринт
не включает её свет и не отключает выбранные для этой записи автоматизации.
Ночью работает обычное сохранение, включение и восстановление.

Условие проверяется перед новым включением. Сам восход/закат не запускает
переключение света. Если свет уже изменён, смена положения солнца не мешает
восстановить его и вернуть автоматизации после выезда или прибытия на базу.
При недоступном `sun.sun` правила «над/ниже горизонта» не разрешают новое
включение; «Всегда» продолжает работать. Дополнительный помощник не нужен.

### Приостановка автоматизаций на время уборки

В каждой записи комнаты есть поле **«Приостановить автоматизации»**. Выберите,
например, автоматизации света по движению этой комнаты. После подтверждённого
въезда их текущие действия останавливаются, а сами автоматизации отключаются.
При выезде сначала восстанавливается свет, затем включаются только те
автоматизации, которые были включены до въезда. На базе и при недоступности
робота действует то же восстановление. При паузе в комнате они остаются отключены.

Для этой возможности создайте один **текстовый помощник** (`input_text`)
с максимальной длиной **255** и выберите его в разделе 1 блюпринта. Помощник должен
быть отдельным для этой автоматизации; при настройке через YAML не задавайте
`initial`, чтобы сохранённый журнал восстанавливался после перезапуска HA.
Если списки автоматизаций пусты, помощник не нужен и прежние настройки работают.

Настройка помощника один раз: **Настройки → Устройства и службы → Помощники →
Создать помощник → Текст**. Назовите его, например, «Dreame — возврат автоматизаций»,
укажите максимальную длину **255**, затем выберите его в поле
**«Текстовый помощник для восстановления автоматизаций»** блюпринта.

Если журнал не помещается, недоступен или уже принадлежит другой автоматизации,
блюпринт покажет уведомление и не станет отключать новые автоматизации.

Сам блюпринт исключается из отключаемых сущностей. Не удаляйте и не меняйте
его помощник во время уборки; перед отключением или редактированием блюпринта
дождитесь возвращения робота на базу. Журнал переживает перезапуск, но восстановление
требует, чтобы автоматизация Dreame оставалась включённой. Динамические снимки
**света** по-прежнему не переживают перезапуск HA.

### Обновление с первой версии

Первая версия [dreame_room_light.yaml](dreame_room_light.yaml), требовавшая отдельную автоматизацию на комнату, оставлена для совместимости. Новый файл называется **dreame_room_lights.yaml**.

Дождитесь возвращения робота на базу и восстановления света. Отключите прежние автоматизации света Dreame, импортируйте новый файл кнопкой выше и создайте одну новую автоматизацию. Одновременно обе версии для одних ламп запускать не нужно.

### Что учитывать

- Снимки `scene.create` временные: перезапуск Home Assistant или перезагрузка сцен удаляет их. Перед этим, а также перед изменением списка комнат или отключением автоматизации, дождитесь восстановления света.
- Восстанавливаются состояние включения и поддерживаемые интеграцией параметры света. Для ранее выключенной лампы сцена выключает её; восстановление внутренних запомненных цвета/яркости выключенной лампы зависит от устройства. Динамические палитры производителя могут восстанавливаться не полностью.
- Ручные изменения и команды других автоматизаций во время присутствия робота при выезде заменяются сохранённым состоянием. Недоступную лампу нельзя восстановить до возвращения связи.
- Если хотя бы один выбранный светильник недоступен при въезде, соответствующая запись не применяется. Повторная попытка возможна при следующем событии положения робота.
- Имена сопоставляются по выбранной карте Dreame. Если на разных картах есть одноимённые комнаты, применяется одинаковая настройка. Переименование комнаты в приложении требует обновить её название в форме.

## 🚀 Как установить

Нажмите кнопку **Import Blueprint** напротив нужного файла.

Для ручной установки скопируйте YAML-файл в каталог Home Assistant:

| Тип | Путь |
| --- | ---- |
| Автоматизация (`tv_content_action.yaml`) | `/config/blueprints/automation/personal/tv_content_action.yaml` |
| Автоматизация для всех комнат (`dreame_room_lights.yaml`) | `/config/blueprints/automation/personal/dreame_room_lights.yaml` |
| Скрипт (`alice_smart_speaker_parallel.yaml`) | `/config/blueprints/script/personal/alice_smart_speaker_parallel.yaml` |

Затем перезагрузите автоматизации/скрипты или Home Assistant.
